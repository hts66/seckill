## 修复：客服 WebSocket 聊天「手机端连接中 / 电脑端暂无客户咨询」

**症状**：手机端 WebSocket 一直显示「连接中」，电脑客服端一直「暂无客户咨询」。

**根因**：Spring Cloud Gateway 中 `JwtGatewayFilter` 未加显式 `@Order`，默认排序为
`Ordered.LOWEST_PRECEDENCE`（Integer.MAX_VALUE）；而 `WebsocketRoutingFilter` 的 order 是
`Ordered.LOWEST_PRECEDENCE - 1`。因此 WebSocket 升级请求在鉴权过滤器注入
`X-Internal-Token` / `X-User-*` 头**之前**就被转发到订单服务，订单服务的
`InternalRequestFilter` 因缺 `X-Internal-Token` 返回 403「请通过网关访问」。
HTTP 走 `NettyRoutingFilter`（同为 LOWEST_PRECEDENCE，靠注册顺序侥幸在鉴权之后），所以 HTTP 正常、WS 挂。

**修复**：让 `JwtGatewayFilter` 实现 `Ordered` 接口（`getOrder()` 返回 `Ordered.HIGHEST_PRECEDENCE`），
排在 WS/HTTP 路由过滤器之前执行。

- 修改文件：`seckill-cloud/seckill-gateway/src/main/java/com/example/seckill/cloud/gateway/JwtGatewayFilter.java`
- 已重新打包并重启网关，握手验证通过（有效 token → 101，空/无效 token → 401）。

**关键坑（务必记住）**：Spring Cloud Gateway 的 `FilteringWebHandler.loadFilters()` 只按
`filter instanceof Ordered` 取顺序，**不识别 `@Order` 注解**。给 GlobalFilter 加 `@Order` 会静默失效
（过滤器仍排 LOWEST_PRECEDENCE）。正确做法是 `implements GlobalFilter, Ordered` + 覆写 `getOrder()`。

**排查技巧（复用价值）**：网关转发 WebSocket 握手返回 403/401 时，先直连下游服务
（带/不带 `X-Internal-Token`）对比响应码，可快速定位是「网关没转发头」还是「下游令牌不匹配」。

**环境备忘**：
- Maven 需 `M2_HOME=D:\app\maven3.9.11\apache-maven-3.9.11`，且用 java 直启
  `org.codehaus.plexus.classworlds.launcher.Launcher`（`mvn` sh 脚本在 Git Bash 下会报 classworlds 找不到）。
- PowerShell 会话若同时存在 `HTTP_PROXY` 与 `http_proxy`（大小写重复），`Start-Process` 会抛「字典关键字重复」；
  需先 `[Environment]::SetEnvironmentVariable('http_proxy',$null,'Process')` 清除小写版。
- `Start-Process -RedirectStandardOutput` 是**覆盖**日志文件而非追加。
- 网关重启命令（后台）：
  `cd seckill-cloud && INTERNAL_TOKEN=<值> NACOS_ADDR=localhost:8848 java -Dcsp.sentinel.log.dir=logs/sentinel -jar seckill-gateway/target/seckill-gateway-1.0.0.jar`

## 增强：商品详情页多图切换 + 修复图片 localhost 问题

**需求**：详情页应能切换查看商品多张图。

**根因**（两个）：
1. 图片 URL 由 MinIO 返回，存的是 `MINIO_PUBLIC_URL=http://localhost:9010`（见 `.env`）。电脑浏览器访问没问题，
   但手机通过局域网 IP 访问前端时 `localhost` 指向手机自身 → 图片加载不出来（与之前 WebSocket localhost 同类坑）。
2. 切换交互只有缩略图、无箭头/计数，体验弱；且 `images.length===1` 时缩略图区不渲染。

**改动**：
- 新增 `src/utils/image.js`：`resolveImageUrl(url)`（把 host 的 localhost/127.0.0.1 替换成 `window.location.hostname`，保留原端口）、
  `parseImageList(imagesJson)`、`firstImage(imagesJson)`。
- `views/SeckillDetail.vue`：`activeImage` 由 ref 改 computed（基于 activeIndex + resolveImageUrl）；新增左右箭头（prevImage/nextImage，环形取模）、
  图片计数「i/N」、缩略图高亮；缩略图 src 也走 resolveImageUrl。
- `views/Home.vue`：`getFirstImage` 改用 `firstImage`（含 host 替换），修复首页列表在手机端的图片加载。

**验证**：前端 `npm run build` 通过（SeckillDetail 5.64kB、Home 7.06kB 均已打包）。

**数据现状**：`seckill_items` 目前只有 id=8、9 两个商品，`product_images` 各 1 张图（products 表为空）。
多图切换需管理员在「商品管理」给商品上传第 2 张图（ImageUpload 组件 `maxCount=5`），保存后秒杀项快照自动同步多图。

**关键机制（复用价值）**：商品图片存 MinIO（bucket=seckill，对象前缀 products/），URL 由 product-service
`store()` 拼 `publicUrl + "/" + bucket + "/" + object` 生成；秒杀项创建时 `ActivityAdminController.insertSnapshot`
通过 `ProductClient.ProductSnapshot.images()` 把商品多图 JSON 快照进 `seckill_items.product_images`。
因此只要商品有多图，秒杀项与详情页自动有多图，前端只负责解析与切换。
